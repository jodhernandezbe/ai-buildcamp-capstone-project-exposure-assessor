## Context

`ComptoxLookup` resolves a DTXSID from a SMILES (the CAS-to-SMILES step comes from a separate PubChem `SmilesLookup`, and molecular weight is calculated with RDKit) (`/chemical/detail/search/by-smiles/`), then reads property and ToxVal data. Live checks (see proposal.md - Why) showed the SMILES search is wrong for aromatic SMILES, and that the ToxVal filters (labels, route) do not match real records. Facts verified live for benzene, toluene, formaldehyde and carbon tetrachloride:

- `/chemical/search/equal/{casrn}` returns `[{dtxsid, casrn, preferredName, searchName: "CAS-RN", smiles, ...}]`; an unknown CAS returns HTTP 400 with `detail` "Searched by CASRN: Found 0 results ..."; a bare number such as `71432` is matched as `searchName: "Substance_id"` and returns an unrelated chemical.
- ToxVal types seen: `RfD`, `RfC`, `cancer slope factor`, `cancer unit risk` (plus provisional and other variants). Units: `mg/kg-day`, `mg/m3`, `(mg/kg-day)-1`, `(mg/m3)-1` (and one `(mg/L)-1`). `exposureRoute` is `oral`, `inhalation`, `dermal` or `not specified`; slope-factor records exist for both oral and inhalation (subtypes `oral slope factor`, `inhalation slope factor`). IRIS lists duplicate records and, for cancer values, a low/high pair.

## Goals / Non-Goals

**Goals:**
- Never report data for a chemical other than the one requested.
- Select toxicity values by label, route and a stated conservative rule.

**Non-Goals:**
- Computing molecular weight ourselves, or finding it for chemicals CompTox has no mass for (it is simply unavailable).
- Using provisional values (`RfC (provisional)` etc.), PPRTV fallbacks, or study-level detail (subtype, effect, species).
- Filtering on `qualifier` or `humanEco` (always `=` and human health in all inspected records).

## Decisions

1. **Resolve by CAS, not SMILES.** `ComptoxLookup.get_properties(cas)` / `get_toxicity_values(cas)`; config key `dtxsid_by_cas_path = "/chemical/search/equal/{casrn}"` replaces `dtxsid_by_smiles_path` (loader: `dtxsid_by_cas_url`, `{casrn}` placeholder required). Alternative considered: keep the SMILES search and Kekulize first; rejected because it matches by structure through an endpoint that already misbehaved silently, whereas the CAS search is the identifier the user supplies and can be verified exactly.
2. **Verify the match.** Accept a result only if `searchName == "CAS-RN"` and its `casrn` equals the requested hyphenated CAS; otherwise treat as no match (debug-logged). This guards against the substance-ID trap and any future endpoint drift. First verified result wins.
3. **CAS validation and normalization** in a new `tools/informatics/helpers/cas.py`: `format_cas(raw) -> str | None` strips whitespace, accepts hyphenated or bare digits (2-7 digits, 2 digits, 1 check digit), verifies the check digit, and returns `NNNNNNN-NN-N`; None if invalid. Applied by the CompTox helper before any request and cache lookup, so cache keys are the hyphenated form. Invalid input returns empty without a request.
4. **HTTP 400 handling.** In the DTXSID step only, HTTP 400 whose JSON `detail` contains "Found 0 results" is a definitive no-match (cacheable); other 400s stay transient failures. Property and ToxVal steps keep the current rules (404 definitive, other non-200 transient).
5. **Toxicity config.** Each `[[comptox.toxicity_values]]` gains `routes` (non-empty list, compared lower-cased) and `prefer` (`"lowest"` or `"highest"`). Defaults: `rfd` types `["RfD"]`, routes `["oral", "not specified"]`, lowest; `rfc` types `["RfC"]`, routes `["inhalation", "not specified"]`, lowest; `sf` types `["cancer slope factor"]`, routes `["oral"]`, highest; `iur` types `["cancer unit risk"]`, routes `["inhalation"]`, highest. "not specified" is accepted only for RfD and RfC, whose names fix the route; slope-factor and unit-risk records with unspecified route are not trusted. Provisional labels are simply not listed. Alternative: derive route from `toxvalSubtype`; rejected because subtype is "-" for RfD/RfC and sparse elsewhere, while `exposureRoute` is present on every record.
6. **Selection order:** filter (label, route, numeric, unit) -> rank by `source_priority` -> keep the best-ranked source's records -> pick lowest/highest by `prefer` -> first on ties. "Most conservative" protects the user: a lower reference value or higher potency gives a higher computed risk. Documented in the tool docstring.
7. **Units.** Add aliases `(mg/m3)-1 -> 1/(mg/m^3)` and `(mg/L)-1 -> 1/(mg/L)`. The latter converts dimensionally but an Alaska DEC IUR in that unit looks mislabeled; it only matters when no better-ranked source exists, and the source is reported.
8. **Tool flow.** `lookup_chemical_properties` validates the CAS (invalid or blank -> all-None result, one warning, no requests, no key needed), then queries CompTox by CAS for molecular weight, properties and toxicity values. CompTox is the only data service. A CAS CompTox does not know gives the all-None result plus one warning; a known CAS without a molecular weight gives molecular weight None plus a warning while the other fields are still returned. A missing API key raises as before, but only for valid CAS numbers.
9. **Tests.** Unit tests change from SMILES to CAS inputs and add: bare-number CAS, bad check digit, `Substance_id` trap, 400 zero-results, route filter, conservative selection, dedupe of identical records. The existing smoke tests become the acceptance check; add smoke cases for a bare-number CAS and an invalid CAS.
10. **Defensive programming principles applied** (each is a reviewable rule for this change):
    - *Validate at the boundary, once.* CAS input is validated and normalized before any request or cache access (decision 3); config is validated at load.
    - *Fail closed.* Anything unverified (wrong `searchName`, different CAS, record for another DTXSID, wrong type, non-finite number) becomes "absent" with a warning, never a coerced or best-effort value.
    - *Treat external data as untrusted.* Every field used from CompTox is type-checked (`isinstance`) before use, `bool` is not accepted as a number, and records whose `dtxsid` differs from the requested one are skipped.
    - *Plausibility guard.* After conversion the tool rejects values that are not finite and strictly positive (the risk models require positive benchmarks), with a warning. The helper stays a faithful passthrough; the guard lives in the tool layer next to the unit conversion.
    - *Separate setup errors from data problems.* Missing API key and invalid configuration raise; unknown chemicals, bad units and bad values produce warnings. No bare `except`; each handler names the exceptions it expects.
    - *No shared mutable state escapes.* Cached dicts are copied on return (including nested `sources`/`warnings` containers), and settings are frozen dataclasses with tuple fields.
    - *Bounded work.* Every request has the configured timeout; CAS input is length-bounded by its format; no retries or unbounded loops are added.
    - *Be explicit about decisions.* Each filter and tie-break rule is documented in the docstring and in config, and each has a negative test.

11. **Remove the stale SMILES lookup and RDKit.** After decision 1 nothing needs a CAS-to-SMILES step, and molecular weight is available from CompTox itself: `GET /chemical/detail/search/by-dtxsid/{dtxsid}` returns an object with `averageMass` (g/mol), `monoisotopicMass` and `molFormula` (checked live for benzene 78.114, toluene 92.141, formaldehyde 30.026, carbon tetrachloride 153.81 and water 18.015, each agreeing with RDKit to within 0.02). The property summary has no molecular-weight entry, so the detail endpoint is used, configured as `detail_by_dtxsid_path`. Delete `tools/informatics/helpers/smiles.py` (`SmilesLookup`, `normalize_cas`, `canonicalize`), `molecule.py` and their tests, `PubChemSettings`/`load_settings`/`get_settings`, the `[pubchem]` table and its tests, the exports in `helpers/__init__.py` and `config/__init__.py`, and the `rdkit` dependency (`pyproject.toml`, `uv.lock`). The CAS search response is parsed into a frozen `Chemical(dtxsid)` cached per CAS and shared by all three lookups; `ComptoxLookup.get_molecular_weight(cas)` fetches `averageMass`, requires a finite number, and caches it. The response field name, the unit the API reports it in (the response carries none) and the target unit are configured in a `[comptox.molecular_weight]` table (`field = "averageMass"`, `unit = "g/mol"`, `target_unit = "g/mol"`) so nothing about the service's schema is hardcoded, and molecular weight passes through the same unit guardrail as every other value. Alternative: keep RDKit to calculate it; rejected as a heavy dependency for a value the service already provides, and it avoids a second source of truth. The reported source for molecular weight changes from "calculated" to "CompTox".

13. **Toxicity context for the final answer.** `ToxicityValue` gains `route` (as recorded, lower-case), `endpoint` (`toxicologicalEffect`) and `assessment` (`riskAssessmentClass`, lower-case), each from the chosen record; "-", blank and non-text become None. The tool adds `toxicity_details: dict[str, ToxicityDetail]` with `source`, `exposure_route` (the first accepted route in config, i.e. the route the value applies to), `route_reported` (the record's own route, which can be "not specified" for RfD/RfC) and the endpoint and assessment. `sources` is kept unchanged. Alternative: put the context into `sources`; rejected because `sources` is a flat string map shared with properties. `toxvalSubtype` ("chronic", "oral slope factor") and `sourceUrl` were considered and left out to keep the output compact; both are single-field additions later.

## Risks / Trade-offs

- [The CAS endpoint may change or rate-limit] -> Endpoint path is config; verification step turns drift into "no match" rather than wrong data; smoke tests detect it.
- [Conservative picks overstate risk when IRIS gives a plausible range] -> Intentional for screening; the choice is per entry in config and documented.
- [Accepting "not specified" for RfD/RfC might admit a mislabeled route] -> Limited to types whose names imply the route; source is reported.
- [Rejecting CAS numbers with a bad check digit may block a real but odd CompTox CAS] -> Surfaced as a clear warning; acceptable for screening input.
- [Plausibility guard could reject a legitimate zero (e.g. a reported 0 reference value)] -> A zero benchmark is unusable in the risk models anyway; the warning tells the user why.
- [CompTox may hold no average mass for some substances (e.g. mixtures)] -> Reported as None with a warning; the other fields still return.
- [`averageMass` uses CompTox's atomic weights, so it can differ from other tools in the third decimal] -> Immaterial for screening; the source is reported.
- [Changing helper signatures breaks the only caller] -> The tool is the only caller and is updated in the same change.
